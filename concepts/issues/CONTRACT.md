# Контракт: тело выпуска как фрагмент для сайта

- Выпуск = два файла: `concepts/issues/<slug>.html` (этот контракт) и `<slug>.meta.json` (META.md). Больше ничего не трогать: сайт подхватит выпуск сам.
- Портретов нет: злодей — постер-эмблема, как у 10–22.
- Публикация только после «да» Адама: push в `main` сразу выкладывает сайт. До этого работать в своей ветке.

Каждый выпуск хранится в одном файле `concepts/issues/<slug>.html`. Это ФРАГМЕНТ, а не страница: без doctype, html, head и body. Сайт сам рисует шапку выпуска (портрет, обложку, «Что ты узнаешь»), а фрагмент вставляется сразу под ней.

## Структура фрагмента
```html
<section class="ix ix-<slug>" data-ix="<slug>"> ...разметка... </section>
<style> /* КАЖДЫЙ селектор начинается с .ix-<slug> */ </style>
<script>(function(){ var root=document.querySelector('.ix-<slug>'); if(!root) return; /* весь JS только внутри root */ })();</script>
```

Правила:
- Ни одного глобального селектора: никаких `body`, `html`, `*` и `:root` без префикса `.ix-<slug>`. Глобальных переменных JS тоже нет.
- Внешних запросов нет. Шрифты «Rubik», «Rubik Mono One», «Russo One» и «Neucha» уже подключены на сайте.
- Портреты злодеев указывай как `IMGROOT/villain-N.webp`, где N — номер выпуска. Есть 1, 2, 3, 5, 6, 7, 8, 9. Портрета 4 (Скрипт-Призрак) нет, поэтому его делай типографикой и формами, без мультяшного SVG-персонажа.
- У выпусков 10–22 (Фундамент) портретов тоже нет. Злодея показывай как стильный «постер-эмблему»:
  - крупное имя;
  - символ-предмет (ножницы для кабеля, поддельная печать, змея из букв pip);
  - растр и цвет выпуска.
  
  Так работает Скрипт-Призрак в `xss.html`, посмотри его как пример. Мультяшных персонажей не рисуй.
- Сайт кладёт фрагмент в колонку шириной около 900px с полями. Если нужен кадр во весь экран (кино), растяни его так: `width:100vw; margin-left:calc(50% - 50vw)`. Горизонтального скролла быть не должно.
- `id` уникальны и начинаются с `ix-<slug>-`.
- Если JS перерисовывает DOM, делай это только внутри root.

## Что обязано быть в каждом выпуске
Адам просил это прямо:
1. Основная история в одном из трёх стилей (смотри ниже).
2. Действия **по клику**, а не только по скроллу. На каждом шаге одна понятная кнопка с глаголом («Отправить запрос», «Поменять номер»…).
3. **«Битва со злодеем»** после истории: 3 хода злодея. Читатель выбирает правильную защиту из 2–3 вариантов, видит шкалу HP злодея и реакцию «УДАР!» или «промах» с объяснением в одну строку. В конце «<Злодей> повержен», счёт и кнопка «Ещё раз».
4. **«Вопрос с собеседования»** уровня junior AppSec. Сначала «Подумай сам» с подсказкой, затем кнопка «Показать сильный ответ». Ответ состоит из 3–4 пунктов с жирным заголовком у каждого и строки «Ошибка новичка: …». Крупно, контрастно, читабельно.
5. **«Шпаргалка: что важно знать»**: 5–7 пунктов. В каждом крупный жёлтый номер с обводкой («01»), короткий заголовок шрифтом Russo One (около 21px) и одна фраза (18px). Между пунктами тонкие разделители, без коробки вокруг каждого пункта.
6. Одна строка о легальной практике: picoCTF, PortSwigger Web Security Academy, OWASP Juice Shop (по теме можно добавить TryHackMe или HackTheBox Academy). Чужие сайты трогать нельзя.

Квиз, сноски и вопрос с собеседования, которые сайт рисует сам, при наличии фрагмента скрываются. Поэтому всё нужное должно быть во фрагменте.

## Три стиля (их Адам назвал крутыми, других не изобретать)
Смотри готовые образцы:
- **A. «Кино»**: `concepts/a/index.html`, нужная часть начинается сразу после шапки. Липкая сцена во весь экран, по скроллу или по кнопке письмо или объект движется, крупный план портрета злодея с растром, один сильный момент «вау». Внизу кадра док с одной жёлтой кнопкой и счётчиком «кадр N/12».
- **B. «Комикс-разворот»**: `concepts/b/index.html`. Страницы с панелями и гаттерами, наклоны, растр, SFX, сплэш-панель кульминации.
- **C. «Играбельная миссия»**: `concepts/c/index.html`. Экран задания, уровни, шкала защиты, «ВЗЛОМ!» с откатом, читатель сам чинит.

Посмотри на скриншоты в этих папках.

## Прокрутка
- Не вызывай `focus()` или `scrollIntoView` при загрузке: страница должна открываться с шапки.
- Кино должно корректно показывать стартовый кадр, если страница открылась вверху.
- Если страница открылась уже прокрученной, состояние должно соответствовать реальной позиции, без «прыжков».
