СОНЯА кто тогда выполняет команды?
ДЯДЯ МИШАШелл. У нас это bash. Смотри, что он делает со строкой.
Терминал

sonya@kruzhok:~$ grep -c "Failed" auth.log

bash режет строку на слова:

grepкоманда -cфлаг: «только посчитай» Failedаргумент: что искать auth.logаргумент: где искать

1338

Заметила? Кавычки исчезли. "Failed" превратилось в Failed ещё до запуска grep.

Кто разрезал строку на слова и снял кавычки?

▢Терминал — окно: экран и клавиатура. Его можно поменять, команды останутся те же.

$Шелл — переводчик между тобой и системой: bash, zsh, sh. Он режет строку и запускает программы.

Любая команда устроена одинаково: программа, потом флаги с дефисом (как работать), потом аргументы (над чем работать).

    ДЯДЯ МИШАВолшебства не будет. Напишем свой скрипт: короткий, и каждую строку ты понимаешь.
    


    #!/usr/bin/env bash
# ↑ шебанг: чем исполнять файл
set -u   # нет переменной — стоп
LOG="/var/log/kruzhok/auth.log"
TOP=$(grep "Failed" "$LOG" \
  | awk '{print $2}' | sort \
  | uniq -c | sort -nr | head -1)
COUNT=$(echo "$TOP" | awk '{print $1}')
IP=$(echo "$TOP" | awk '{print $2}')
if [ "${COUNT:-0}" -gt 100 ]; then
  ufw deny from "$IP"
  echo "$(date) $IP" >> bans.log
fi
    
    
    Тот же конвейер, только внутри $( … ): вывод команды кладём в переменную. ufw deny — добавить правило файрвола «не пускать этот IP».

    ВОПРОС С СОБЕСЕДОВАНИЯ · JUNIOR APPSEC
    
  
    В инструкции к утилите написано: «Установка: curl … | sudo bash». Чем это опасно и как бы ты поставил её безопасно?
    
  
    
    Подумай сам
    Подсказка: кто видит код до запуска? С какими правами он выполняется? И что гарантирует HTTPS, а что нет?
  
    
  
  
    
    
      
      
    1. Что происходит. Код с чужого сервера сразу выполняется с правами root. Никто его не прочитал, ничто его не проверило.
      2. 
      
    2. Риски. Взлом сайта или зеркала, подмена файла для curl | bash, обрыв загрузки посреди строки. HTTPS защищает дорогу, а не намерения автора.
      3. 
      
    3. Как безопасно. Пакетный менеджер, если есть. Иначе скачать файл, сверить подпись или SHA-256 из независимого источника, прочитать, сначала запустить в виртуалке, с минимальными правами.
      4. 
      
    4. Свои скрипты. Кавычки вокруг переменных, set -euo pipefail, проверка ShellCheck, никаких паролей в аргументах команд.
      5. 
    
    
    
    Ошибка новичка: «Там же HTTPS и известный сайт — значит, безопасно». HTTPS гарантирует, что файл не подменили по дороге, но не что в нём нет вреда.

    Терминал
    Окно для текста: показывает вывод и передаёт нажатия клавиш, но сам команды не выполняет
    Шелл (bash)
    Программа, которая читает строку, делит её на слова и запускает команды
    Конвейер (pipe)
    Символ |, который отдаёт вывод одной команды на вход следующей
    Перенаправление
    > пишет вывод в файл с перезаписью, >> дописывает в конец, 2> уводит ошибки
    Код выхода
    Число, которое команда возвращает по завершении: 0 — успех, всё остальное — ошибка или «не найдено»; смотреть в $?
    Шебанг
    Первая строка скрипта вида #!/usr/bin/env bash, которая говорит системе, чем его исполнять
    Вопрос с собеседования
    В инструкции к утилите написано «curl … | sudo bash». Чем это опасно и как установить её безопасно?
    Такая строка сразу выполняет код с чужого сервера с правами root, и никто его не читает. Сайт или зеркало могут взломать, сервер может отдать curl | bash другой файл, а при обрыве загрузки bash выполнит половину строки. HTTPS защищает дорогу, а не намерения автора. Безопасно так: пакетный менеджер, а если его нет — скачать файл, сверить подпись или SHA-256 из независимого источника, прочитать, сначала запустить в виртуалке и с минимальными правами. В своих скриптах — кавычки вокруг переменных, set -euo pipefail, ShellCheck и никаких паролей в аргументах команд.
    Практиковаться можно только там, где это разрешено: picoCTF, PortSwigger Web Security Academy, OWASP Juice Shop. Чужие сайты без разрешения трогать нельзя.
