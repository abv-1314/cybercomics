Стр. 1

Почему Python

Серверная НИИ. Три часа ночи по логам. Чай в подстаканнике уже остыл.

СоняДядя Миша, а почему все безопасники пишут на Python? Это же язык для начинающих.
Дядя МишаПотому и пишут. Ночью, на усталую голову, код должен читаться как записка, а не как шифровка.
  1. Читается как текст. Отступы вместо скобок, мало лишних знаков.
  2. Батарейки в комплекте. Файлы, сеть, JSON, хеши — уже в стандартной библиотеке.
  3. Готовые инструменты. sqlmap, Volatility, Impacket написаны на Python.
Для чего он безопаснику

Скучное — скрипту.

Разобрать тысячу строк лога, сверить список адресов, проверить сто сайтов на свежий сертификат. Человек устаёт и пропускает. Скрипт — нет.

    Стр. 5
    Три головы
    

    
  
    
    
    
      01
      
    Опечатка
    
      
    reqeusts
    
      
    Злодей регистрирует имя, похожее на популярное, и ждёт, когда палец дрогнет. Это называют тайпсквоттингом. В марте 2024 года PyPI даже временно закрывал регистрацию новых проектов, отбиваясь от волны таких двойников.
    
    
    
  
    
  
    
    
    
      02
      
    Скрипт установки
    
      
    setup.py
    
      
    Если пакет приходит исходниками, при установке pip запускает его сборку — обычный Python-код с твоими правами. Вредный код не ждёт import: он срабатывает уже на pip install.

    Дядя МишаИ ещё. Токен чата в коде не пиши. Код уезжает в git, в скриншоты, в чат «глянь, что не так».
    
      
    
        
    Так нельзя
    TOKEN = "7312:AAHk9x…"
    
        
    Так правильно
    import os
TOKEN = os.environ["CHAT_TOKEN"]
    
      
    
      
    Токен живёт в переменной окружения. Нет переменной — скрипт честно падает, а не работает с чужим ключом.

    Junior AppSec
    Вопрос с собеседования
    

    
  
    Как защитить Python-проект от атак через зависимости?
    
  
    Подумай сам. Подсказка: вспомни три головы Пипыча — откуда приходит пакет, что он делает при установке и сколько ему лет.
    
  
  
    
    
    Откуда пакет. Проверяю имя и источник: страницу на pypi.org, ссылку на репозиторий, историю релизов. Внутренние пакеты беру только из внутреннего индекса, иначе можно попасть на dependency confusion.
    
    
    Воспроизводимость. Отдельный venv на проект, точные версии и хеши в requirements.txt, установка с --require-hashes. Файл с хешами генерирую инструментом, например pip-compile.
    
    
    Код при установке. Сборка из исходников запускает код с правами пользователя. Предпочитаю готовые wheel-файлы и ставлю зависимости в CI или контейнере, где нет секретов.
    
    
    Известные уязвимости. SCA в CI: pip-audit или Dependabot. Закреплённые версии регулярно обновляю, а не забываю на годы.
    
    
    Ошибка новичка: «у меня venv, значит, безопасно» или «версия закреплена — значит, защищён навсегда».

    Что такое PyPI?
    PyPI — Python Package Index — общий открытый склад пакетов Python, откуда pip их скачивает.

    Словарик
    PyPI
    Python Package Index — общий открытый склад пакетов Python, откуда pip их скачивает.
    pip
    Стандартная программа для установки пакетов Python.
    venv
    Отдельная папка с пакетами для одного проекта. Разделяет проекты, но не защищает от вредного кода.
    Тайпсквоттинг
    Пакет с именем, похожим на популярное, рассчитанный на опечатку.
    CVE
    Общий номер для публично известной уязвимости, например CVE-2018-18074.
    SCA
    Software Composition Analysis: проверка зависимостей по базе известных уязвимостей. Пример — pip-audit.
    Вопрос с собеседования
    Как защитить Python-проект от атак через зависимости?
    Проверять имя и источник пакета: страницу на pypi.org, репозиторий, историю релизов, а внутренние пакеты брать только из внутреннего индекса. Держать отдельный venv на проект, закреплять точные версии с хешами и ставить с --require-hashes. Помнить, что сборка из исходников запускает код с правами пользователя: предпочитать wheel-файлы и ставить зависимости там, где нет секретов. Запускать SCA вроде pip-audit в CI и регулярно обновлять закреплённые версии.
    Практиковаться можно только там, где это разрешено: picoCTF, PortSwigger Web Security Academy, OWASP Juice Shop. Чужие сайты без разрешения трогать нельзя.
