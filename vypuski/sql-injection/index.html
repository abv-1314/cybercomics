Так нельзя 
name = request.form["username"]
query = "SELECT * FROM users WHERE name = '" + name + "'"
db.execute(query)   # ввод стал частью SQL
Так правильно 
cursor.execute(
    "SELECT * FROM users WHERE name = %s",
    (name,)   # значение уходит отдельно
)

Здесь %s — не склейка, а метка для значения. В других библиотеках она выглядит как ? или :name.

Стр. 5

Подвохи

СоняА если я пользуюсь ORM, я в безопасности?
Дядя МишаПочти. ORM сама подставляет параметры. Но если внутри неё склеить «сырой» запрос со строкой — дыра вернётся.

ORM — библиотека, которая работает с базой через объекты кода вместо ручного SQL.

Сортировка: ?sort=price

Имя колонки и направление сортировки параметром не передать.

ALLOWED = {"name", "price", "date"}
if sort not in ALLOWED:
    sort = "name"

Сверяй со списком разрешённых значений.

Что такое SQL-инъекция?

SQL-инъекция — атака, при которой ввод пользователя встраивается в текст SQL-запроса и меняет его смысл: база не отличает данные от команды.

Словарик

SQL
Язык запросов к базам данных: найти, добавить, изменить, удалить записи.

Принцип least privilege: у учётной записи есть только те права, без которых не обойтись.

Вопрос с собеседования

Что такое SQL-инъекция и как от неё защититься?

Это уязвимость, при которой ввод пользователя встраивается в SQL-запрос и меняет его смысл. Причина — склеивание строк: база не отличает данные от команды. Последствия: обход входа, утечка и изменение данных, иногда выполнение команд на сервере. Защита: параметризованные запросы или ORM, список разрешённых значений для имён колонок, минимальные права учётной записи базы, никаких подробных ошибок наружу. WAF и валидация — дополнительный слой. В пайплайне инъекции ловят SAST и DAST.

Практиковаться можно только там, где это разрешено: picoCTF, PortSwigger Web Security Academy, OWASP Juice Shop. Чужие сайты без разрешения трогать нельзя.
